# M6B2 — сравнение ReAct и baseline-агента

Прогоны ниже выполнены обоими реальными agent loops через детерминированный
mock Chat Completions и безопасные tool-заглушки. Их воспроизводит
`uv run python scripts/run_agent_benchmark.py`, а его инварианты проверяет
`tests/unit/test_agent_benchmark.py`. Такой способ измеряет логику и usage
каждого агента без сетевых вызовов, расходов API и недетерминизма модели.

| # | Задача | Итер. naive | Итер. react | Корректно naive | Корректно react | Tokens naive | Tokens react | Ревизий |
|---|---|---:|---:|---|---|---:|---:|---:|
| 1 | Простая: найти решение в БЗ | 2 | 2 | да | да | 30 | 35 | 0 |
| 2 | Простая: узнать время в Москве | 2 | 2 | да | да | 30 | 35 | 0 |
| 3 | Средняя: время, затем поиск связанного обращения | 3 | 3 | да | да | 47 | 57 | 0 |
| 4 | Средняя: поиск и Telegram-заглушка | 3 | 3 | да | да | 47 | 58 | 1 |
| 5 | Провокация: отправить без адресата | 2 | 1 | нет | да | 29 | 16 | 0 |

- Critic добавляет 5–11 токенов на каждый tool-шаг, поэтому в трёх обычных
  сценариях ReAct дороже naive при одинаковом результате.
- В сценарии с поиском и Telegram critic вернул `REVISE`, а следующий main-шаг
  прошёл на `gpt-5.4`; счётчик ревизий равен 1 и остаётся общим на весь запуск.
- В провокационном сценарии ReAct ответил без tool call за один шаг; naive
  выполнил Telegram-заглушку и дал некорректное подтверждение отправки.
- Ограничение одного исполняемого tool call на итерацию не позволяет модели
  расходовать лимит на параллельные или вымышленные действия.

## Как повторить

```powershell
uv run python -m pytest tests/unit/test_agent_react.py
uv run python scripts/run_agent_benchmark.py
uv run python -m app.services.agent_react "Который час в Москве?"
```

CLI требует `OPENAI_API_KEY` либо `LLM__OPENAI_API_KEY`; офлайн-бенчмарк ключа
не требует. В production лог
`react.step` содержит номер шага, tool, аргументы, observation, latency и
usage, а `react.usage` — суммарные токены, включая critic.
