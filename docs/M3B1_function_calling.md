## Проверка полного цикла Function Calling

Реализован полный цикл function calling для ассистента технической поддержки:

1. Описание функции через JSON Schema.
2. Отправка пользовательского запроса в модель вместе со списком tools.
3. Получение ответа модели.
4. Проверка наличия `tool_calls`.
5. Выполнение Python-функции `search_knowledge_base`.
6. Добавление результата функции в историю сообщений с ролью `tool`.
7. Повторный запрос к модели.
8. Получение финального ответа пользователю.

### Используемый tool

`search_knowledge_base(query, ips)`

Назначение: поиск типовых решений в базе знаний техподдержки.

Параметры:

* `query` — краткое описание проблемы пользователя.
* `ips` — одно ответственное подразделение или группа поддержки. Допустимые значения: `""`, `"АИС Правоохрана"`, `"АИС ЦРСВЭД"`, `"АИС Постконтроль"`.

---

### Сценарий 1. Запрос точно требует tool

Пользовательский запрос:

```text
В АИС Правоохрана пользователь не входит в систему, пишет access denied. Есть типовое решение?
```

Результат:

```text
Модель вызвала tool: да.
Имя tool: search_knowledge_base.
Аргументы: query = "Пользователь не может войти в систему, пишет access denied", ips = "АИС Правоохрана".
Функция нашла запись базы знаний: "kb-001", "Ошибка авторизации в АИС Правоохрана".
Финальный ответ модели: "модель указала причину access denied, перечислила проверки учетной записи, ролей, блокировки и срока действия пароля, затем рекомендовала направить заявку администратору АИС Правоохрана"
usage.total_tokens: "2221".
```

Вывод: модель корректно определила, что запрос содержит конкретную техническую проблему, вызвала `search_knowledge_base`, получила результат из базы знаний и сформировала финальный ответ пользователю.

---

### Сценарий 2. Запрос точно не требует tool

Пользовательский запрос:

```text
Что такое база знаний в техподдержке?
```

Результат:

```text
Модель вызвала tool: нет.
tool_calls: [].
Финальный ответ модели: "Дала развернутое объяснение, что такое база знаний и какие функции она выполняет"
usage.total_tokens: "912".
```

Вывод: модель корректно определила, что вопрос является общим теоретическим и не требует поиска по базе знаний.

---

### Сценарий 3. Пограничный случай

Пользовательский запрос:

```text
Как обычно разбирают ошибку 500 в приложении?
```

Результат:

```text
Модель вызвала tool: нет.
tool_calls: [].
Финальный ответ модели: Описана ошибка, также даны шаги для диагностики и устранения такой ошибки.
usage.total_tokens: 974.
```

Вывод: модель обработала запрос как общий методический вопрос и не вызвала tool. Запрос является пограничным, потому что содержит технический симптом, но не указывает конкретную АИС и не содержит прямую просьбу искать типовое решение в базе знаний.
